# notes
## threat vs vuln vs exploit vs risk

| component | purpose                                        |
| :-------- | ---------------------------------------------- |
| threat    | potential source of attack or harm             |
| vuln      | weakness that can be targeted                  |
| exploit   | technique used to abuse a vuln                 |
| risk      | probability and impact of a successful exploit |

## questions
~~what makes "broken access control" different from "authentication failure"?~~ - auth fails happen *because* of broken access controls
## opinions
- major uptick in supply chain attacks as the main application gets secured while the software it depends on is often overlooked or the risk is accepted. could also attribute this to AI apps and their underlying models
	- top concern for application owners
- ~~SSRF is no longer on there because as applications have gotten more complicated, they solve for these easily-fixed problems first~~ - nvm, this is still a problem
- nothing specific to AI because [[30 - Ideaverse/AI systems are vulnerable to the same vulnerabilities as software systems\|AI apps have the same vulnerabilities as software apps]] 
- a lot of these can be solved by [[30 - Ideaverse/Security by design\|involving security in the design process]] 
- zero-trust compensates for failure to maintain trust boundaries ✅
- ==things that are hard to test for==: logging & alerting, worst-case scenarios, insecure user behavior, supply chain failures
- ==things that are easy to test for==: insecure design, injection, broken access control
- design for the worst case scenario
- situation, task, action, result (STAR)

# Top ten lists
## 2021
1. Broken access control
2. Cryptographic failures
3. Injection
4. Insecure design
5. Security misconfiguration
6. Vulnerable and outdated components
7. Identification and authentication failure
8. Software and data integrity failures
9. Security logging and monitoring failures
10. Server side request forgery (SSRF)

## 2025
1. Broken access control (=, SSRF rolled in to this)
2. Security misconfiguration (+3)
3. Software supply chain failures (NEW)
4. Cryptographic failures (-2)
5. Injection (-2)
6. Insecure design (-2)
7. Authentication failure (=, but used to be Identification and authentication failures)
8. Software and data integrity failures (=)
9. Security logging and alerting failures (=, but used to be monitoring failures)
10. Mishandling of exceptional conditions (NEW)
